## Findings

1. **P2 — The binary export guard can miss a matching secret.** `scripts/public_export.sh:24` pipes SQLite output into `grep -q` under `set -o pipefail`. When a match occurs early in a large dump, grep exits successfully before SQLite finishes. SQLite receives SIGPIPE, so the pipeline returns failure and the `if` skips the rejection. Reproduction on a copy of the shipped database, with `review-sentinel@example.invalid` inserted into the first run row, printed `MISSED`; `${PIPESTATUS[*]}` was `141 0`. This directly defeats the added binary-content check. Write the complete readonly dump to a temporary file before scanning it, or let grep consume the entire stream and handle producer errors explicitly.

2. **P2 — The demo export retains unrelated analyses and unsanitized video payloads.** `scripts/make_demo_db.py:50` keeps every video belonging to an S3 creator. `scripts/make_demo_db.py:52` then keeps every analysis version for those videos, instead of the exact results selected by `run_results`. The shipped database contains 111 videos and 58 analyses, although the run selects 30 videos and 30 analysis versions. That leaves 81 unselected videos and 28 unrelated analysis versions, including `content_v1`, `content_v2`, and `content_v2_repair`. Video JSON retains the raw Kalodata fields, including advertising ratios, ROAS, revenue, and growth. Analysis JSON retains 191 relative `data/media/` path occurrences. The scrubber only allowlists creator JSON and clears `videos.mp4_path`; it does not scrub nested video or analysis fields. On a temporary source copy, adding `private_phone='+84 912 345 678'` and `private_path='/Users/reviewer/private'` to a video payload survived a successful export. Keep only run-selected analysis tuples, allowlist the video fields the web consumes, and sanitize nested payloads before publication. Regenerate `data/demo.db` afterward.

3. **P2 — An interrupted persona pass becomes a completed-looking C comparison.** `scripts/compare_approaches.py:110` treats any stored persona row as an available pass. `src/koc/persona.py:155` averages whatever rows exist, even one video out of three. `scripts/compare_approaches.py:99` then selects fewer than the requested count, while `scripts/compare_approaches.py:160` labels the output Precision@5. A frozen readonly backup taken during the active pass contained 17 of 30 video results across six creators. The committed script exited successfully and reported C as `0/5`, despite selecting only two creators for 10,500,000 VND. Its nDCG denominator also used two ideal positions, while the table said nDCG@5. Require complete coverage of the run's selected videos for one model and prompt version before publishing C, C', or Spearman. Report an incomplete pass explicitly.

4. **P2 — Persona costs include other runs and models.** `scripts/compare_approaches.py:114` sums every uncached `kind='persona'`, `prompt_version='persona_v1'` call in the database. The query does not restrict the chosen model or evaluated run. `src/koc/persona.py:134` deliberately logs `run_id=NULL`, and `BudgetGuard.record` stores an empty request hash, so the comparison cannot recover run attribution from these records. A temporary-copy reproduction added one unrelated persona call for another model at 9 USD. The selected model and scores stayed unchanged, but the reported spend increased by exactly 9 USD, one second, and one call. Preserve the NULL run logging convention if needed, but store a separate evaluation identifier or call mapping and use it to attribute C's cost.

5. **P2 — C and C' drop B's selection constraints.** `scripts/compare_approaches.py:99` filters combinations only by budget. B's `_best_five` also excludes creators from prior runs and rejects duplicate known MCNs. The document says C preserves the selection rules, but these omissions can change the result independently of persona scores. In a temporary database copy, assigning the same known `mcn_id` to all ten S3 creators made B return no valid combination. C still returned five creators from that MCN. Apply the same exclusion and MCN constraints to B, C, and C', with only the documented gate difference for C'.

6. **P2 — The advertised persona estimate is not an upper bound.** `src/koc/persona.py:78` reserves one request per missing video. `src/koc/persona.py:101` permits two billable schema attempts. The estimate also omits frame-label text that `_call` sends and assumes one image tile per frame rather than actual dimensions. An offline fake-client reproduction used eight 360×640 frames and 90 seconds of audio. The dry-run bound was 0.011969 USD. `_call` accepted request bounds of 0.012062 and 0.012290 USD after one malformed JSON response, totaling 0.024352 USD. Both calls passed the guard and were logged. Account for the full schema retry allowance and all request text, and use a proven image-size bound. Until then, remove the CLI's “maximum” wording. The script's pending-C row also advertises a 0.36 USD maximum for 30 calls.

7. **P3 — The interpretation invents a statistical decision threshold.** `docs/eval/COST_EFFICIENCY.md:84`, generated by `scripts/compare_approaches.py:242`, calls a 1/5 gap noise and says a 2/5 gap or two to three briefs permits a conclusion. No uncertainty calculation or sampling design supports those thresholds. The frozen scores support the observed differences, but they do not establish statistical significance. Describe the differences as observations from one rater and one brief. Keep the proposed improvement as a hypothesis.

8. **P3 — The README's test count is stale.** `README.md:13` and `README.md:27` advertise 564 tests, while the committed tree collects 571. Update the count after a complete verified run. Commit `6a88086` fixes the earlier README mismatch about selective video analysis; its C description now agrees with the implementation.
